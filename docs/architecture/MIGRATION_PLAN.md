# Migration plan: gray-box to production (Stage 10)

Principle: **keep what is tested, replace only what is throw-away, and never break the engine's tests while doing it.** Each step ends with `npm run verify` green and the browser audits unchanged. No step needs a framework.

## 1. Classification of the current code

| Area | Files | Fate | Reason |
|---|---|---|---|
| Engine | `src/engine/*` | **Keep**, convert to `.ts` | Pure, 101 tests, fixtures, deterministic replay |
| Store | `src/store/*` | **Keep**, convert | Tested with fault injection; interface already injected |
| Rules | `src/engine/rules.js` | **Keep** | Candidate economy stays switchable; rules id digest stays identical (a changed digest would hold every fixture) |
| Simulator | `src/sim/*`, `scripts/strategy-lab.mjs` | **Keep as dev tools** | Used for balance audits |
| Gray-box UI | `src/ui/app.js`, `ui.css` | **Rewrite in Stage 11** against `publicView` | Built to prove rules, not to ship; 430 lines of unframed DOM |
| Motion prototype | `motion/*` | **Port the maths, rebuild the view** | `camera.js`, `gestures.js`, `transition.js`, `trail.js` are pure and tested (camera tests); `view-camera.js`, `main.js` are prototype views |
| Reveal prototype | `reveal/*` | **Port forms into the production view layer**; keep `lib.js` and the story data | Date maths and coverage logic are tested; story content is sourced and reviewed |
| Pack builder | `tools/pack/*` | **Keep** (Python) | Authoring tool; does not ship |
| Claim checker | `tools/verify/*` | **Keep** (Node + Playwright) | Authoring and CI tool |
| Browser audits | `scripts/e2e-*.mjs` | **Keep, update selectors** with the new UI | Parametrised Playwright path (done) |

## 2. Steps

Each step is one reviewable change set. Steps 1 to 3 are within Stage 11's first week; none changes behaviour.

| # | Step | Gate (must pass before the next step) |
|---|---|---|
| 0 | **Done in Stage 10:** ESLint, `tsc --checkJs` at 0 errors, strict `contracts.ts`, boundary lint rules, CI and Dependabot files | `npm run verify` green: 101 tests, 0 lint errors, 0 type errors |
| 1 | Run CI on a pull request for the first time; fix whatever differs between this container and a clean runner | CI green, or each failure recorded |
| 2 | Add Vite and `vite build` with the current files unchanged; serve the build; add the service worker with a versioned cache and a kill switch | Offline reload works in the audits; kill-switch test |
| 3 | Convert `engine`, then `store`, then `sim` to `.ts` one file at a time, importing types from `contracts.ts` (move the file into `src/types`) | After each file: tests, fixtures, typecheck |
| 4 | Introduce an async-capable storage port and IndexedDB behind it **only if** a trigger (T2) or the archive size requires it | Fault-injection tests re-run against the new adapter |
| 5 | Build the production view layer (Stage 11), starting from `publicView`; port motion maths and Reveal forms | Axe, e2e, reduced motion, 200% text, one-hand check on a **real phone** |
| 6 | Delete the gray-box UI and its selectors once the production view passes the same audits | No references remain; docs link to the replacement |

## 3. Data migrations

- **Pack format.** Add `schema_version` to the pack file at the first change that is not backward compatible. The engine accepts exactly one version at a time; the builder refuses to emit others. Pack fixtures under `app/fixtures` gain a version field and are regenerated by `scripts/demo-run.mjs`.
- **Saved records.** `STATE_SCHEMA` is 1. When it becomes 2: add `Migration{from:1,to:2}` as a pure function, run it on a copy, verify by replaying the stored log when it exists (otherwise by recomputing derived fields), write the new record, keep the old text under `.previous`. A record from a **newer** schema than the app knows is held (`schema_unknown`), never downgraded.
- **Storage key.** The key embeds the schema (`timehunt:v1:…`), so old and new records never collide.
- **Rules.** A rules change that alters outcomes changes `rules.id`; old records are held (`rules_changed`). If a rules change is meant to preserve old games, the migration must carry the old rules object, not reinterpret old state.
- **Rollback.** Migrations are forward-only. Because the old record is kept as `.previous` for one release, rollback means: ship the previous build, which reads the schema-1 record. Records already written as schema 2 are held by the older build, not destroyed.

## 4. Test strategy during migration

- **Characterisation first.** Fixtures (`app/fixtures`) record complete command logs and final digests. They are the contract: a conversion step must reproduce them byte for byte.
- **Property tests** (`properties.test.js`) and the strategy simulator keep running in CI.
- **Boundary lint** blocks any engine import of UI or platform code.
- **Browser audits** (`e2e-ui`, `e2e-reveal`, `e2e-motion`) run on every pull request, and a **real-device pass** is required at the end of Stage 11 (Q-53 to Q-56 are still open).

## 5. Risks of the migration

| Risk | Mitigation |
|---|---|
| TypeScript conversion changes behaviour by accident | One file per change; fixtures and replay must stay identical |
| Rules digest changes and holds every record | The digest input is frozen; a test asserts the current id (**add in Step 3**) |
| Service worker caches a broken build | Versioned cache, kill-switch, test before first deploy |
| Scope creep into framework adoption | Only on a trigger from ADR-001 |
| Real-device problems appear late | Run the existing motion prototype on a phone **before** Step 5 (needs the user's phone) |
